# 開発用サーバーの起動・停止（/dev-up）

## なぜポートを固定するのか

ポートは次の 3 つに決めてある。

| 対象 | ポート | 起動の仕方 |
|---|---|---|
| DB（PostgreSQL・Docker） | 5432 | `backend/` で `docker compose up -d --wait` |
| バックエンド（Spring Boot） | 8080 | `backend/` で `APP_PASSWORD=… ./gradlew bootRun` |
| 画面（Vite） | 5173 | `frontend/` で `npm run dev` |

画面は `/api` を 8080 に転送し、バックエンドは 5432 の DB につなぐ。どれか 1 つでも別のポートで起動すると、つながらなくなる。しかも画面は、ブックマークやユーザーが覚えている URL（http://localhost:5173）とずれる。そのせいで「動作確認がうまくいかない」原因の切り分けに時間を取られる。

そのため、ポートが使われていたら `--port 5174` や `PORT=8081` で逃げずに、**使っている方を止めて、決まったポートで起動する**。画面は `vite.config.ts` の `strictPort: true` で、5173 が使われていると起動せずにエラーになる。Claude Code では、別のポートを指定した起動コマンドを `.claude/hooks/guard-ports.sh` が止める。

## 起動の手順

コマンドはリポジトリのルート（`.claude/` がある場所）から実行する。

1. **Docker を確かめる**: `docker info` が失敗したら `open -a Docker` で Docker Desktop を起動し、`docker info` が通るまで待つ（最大 2 分）。
2. **ポートを空ける**: `bash .claude/skills/dev-up/free-ports.sh`
   - 5173・8080・5432 を使っているプロセスやコンテナを表示してから止める。止めたものは、最後にユーザーへそのまま伝える。関係ないアプリ（ほかのプロジェクトの PostgreSQL など）を止めた可能性があるので、黙っていてはいけない
   - このプロジェクトの DB（`backend-db-1`）が 5432 を使っているときは、止めずにそのまま使う
   - 前に起動したこのプロジェクトの画面やバックエンドも止める。古いコードのまま動いていることがあるので、起動し直すほうが確実
   - exit 1 で終わったら、まだ使われているポートがある。表示されたプロセスをユーザーに伝えて、止め方を相談する
   - プロセスを止める操作が権限の設定で拒否されたら、ほかのやり方で回り込まない。ユーザーに `bash .claude/skills/dev-up/free-ports.sh` を自分のターミナルで実行してもらい、終わったら手順 3 から続ける
3. **DB を起動する**: `cd backend && docker compose up -d --wait`
4. **バックエンドを起動する**: `cd backend && APP_PASSWORD=<パスワード> ./gradlew bootRun` を**バックグラウンドで**実行する（終わらないコマンドなので、前面で実行すると止まってしまう）。
   - パスワードは、環境変数 `APP_PASSWORD` が設定されていればそれを使う。なければ開発用に `devpass` を使う
   - `curl -s -o /dev/null -w '%{http_code}' localhost:8080/api/board` が `401`（ログイン前）か `200` を返すまで待つ（最大 3 分。初回はビルドで時間がかかる）
5. **画面を起動する**: `node_modules` がなければ、先に `cd frontend && npm install` を実行する。そのあと `cd frontend && npm run dev` を**バックグラウンドで**実行し、`curl -s -o /dev/null -w '%{http_code}' localhost:5173/` が `200` を返すまで待つ。
6. **ブラウザで開く**: `open http://localhost:5173`

途中で「ポートが使われている」（`Port 5173 is already in use`・`Port 8080 was already in use` など）で失敗したら、手順 2 からやり直す。ポート番号を変えて回避すると、上に書いた理由でつながらなくなる。

### 最後にユーザーへ伝えること

- 開いた URL（http://localhost:5173）と、ログインのパスワード
- 手順 2 で止めたプロセス・コンテナ（なければ「なし」）
- 止めたいときは「サーバーを止めて」と言えばよいこと

## 再起動の手順

「再起動して」と言われたとき、またはバックエンドのコードを変えたとき（`bootRun` は変更を自動で取り込まない）は、起動の手順を最初から行う。手順 2 で前の画面とバックエンドが止まり、新しいコードで起動し直す。

## 止める手順

「止めて」と言われたら、`bash .claude/skills/dev-up/free-ports.sh --stop` を実行する。画面・バックエンド・このプロジェクトの DB をすべて止める。DB はコンテナを止めるだけなので、データは消えない。

Docker Desktop は、ユーザーに頼まれたときだけ `osascript -e 'quit app "Docker"'` で終了する。ほかのプロジェクトで使っているかもしれないので、勝手には止めない。
